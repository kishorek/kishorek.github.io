How to study this tutor

You will learn to read and write small Java programs, starting from a single instruction and ending with a score report.

No earlier programming class is required. Each new word is explained the first time it appears.

Golden rule. A program is a list of exact steps. The computer follows that list from top to bottom. It does not guess what you meant.

What you will be able to do

  • Explain what a program is, using input, process, and output.
  • Read the starting lines every Java program needs.
  • Store whole numbers, decimals, yes-or-no values, and text.
  • Add, subtract, multiply, divide, and find a remainder.
  • Print messages and read what a person types.
  • Choose with if and else, and repeat with a loop.
  • Name a reusable action, called a method, and use a row of boxes, called an array.
  • Build one small program that uses all of those tools together.

What programming is

Programming is writing exact instructions that a computer can follow.

People can hear a fuzzy request and fill in the gaps. A computer cannot. If a step is missing, or the order is wrong, the result is wrong. That is not the computer being difficult. It is the computer doing exactly what the list says.

Analogy. A recipe is a program for a cook. "Add salt" is too vague, because the cook must guess the amount. "Add 1 teaspoon of salt" is an instruction. A program is a recipe written so carefully that no guessing is left.

A first look at Java

Java is one programming language. This is Java. Each line is one instruction. The computer starts at the top.

Java:

System.out.println("Boil the water");
System.out.println("Pour the water over the tea bag");
System.out.println("Wait two minutes");

Output:

Boil the water Pour the water over the tea bag Wait two minutes

Line by line

  1. System.out.println means "print this, then move to the next line." You will see it in almost every early program.
  2. The words in double quotes are text. They print exactly as written.
  3. The semicolon ends the instruction. It is the period at the end of the sentence.
  4. The next line does not run until the line above it has finished.
Full Java program

A real file needs a frame around those lines. The syntax lesson explains the frame. This is the whole program:

public class Tea {
    public static void main(String[] args) {
        System.out.println("Boil the water");
        System.out.println("Pour the water over the tea bag");
        System.out.println("Wait two minutes");
    }
}

Before

Make tea.

A person might know what you mean. A computer does not know which steps you intended.

After

Boil the water. Pour it over the tea bag. Wait two minutes.

Each step is visible, and the order is part of the instruction.

    How a program works
    
      
    Most small programs do three things: take data in, work on it, and send a result out.
    
      
    Those three parts have names. Input is data that comes in. Process is the work. Output is the result that comes out. A program only knows the input you give it. It does not remember the price from a conversation you had away from the keyboard.
    
      
    Analogy. A cashier receives money (input), subtracts the price (process), and hands you the change (output). If you never say the price, the cashier cannot invent it. Your program has the same limit.

    Java syntax
    
      
    Syntax is the grammar: the rules for how symbols and words may be arranged.
    
      
    English rejects "Cat the sat" even though the words are familiar. Java rejects a line when a semicolon, quote, brace, or capital letter is in the wrong place. A compiler is the checker that translates Java before it can run. If the grammar is wrong, the compiler stops and reports an error. It does not run the program, and it does not fix the line for you.
    
      
    Analogy. A form with required boxes works the same way. If your name is written on the signature line, the form is rejected. The reader does not hunt through the page to guess which line you meant.
    
      
    The boilerplate frame
    
      
    Boilerplate means the same starting lines you wrap around the work. Copy this frame often. Your real steps go where the comment is.
    
      
    Java:
    

    public class Hello {
    public static void main(String[] args) {
        // Your steps go here.
        System.out.println("Hello");
    }
}
    
      
    Output:
    
      
    Hello
    
      
    Line by line
    
      
      
        
    1. public class Hello names the program Hello. The file must be saved as Hello.java. The capital H must match.
      2. 
        
    2. The { } braces group the lines that belong together. Every opening brace needs a closing brace.
      3. 
        
    3. public static void main(String[] args) is the starting point. Java begins there. args can hold extra words typed at startup. You can ignore args for now, but the frame still needs it.
      4. 
        
    4. public means other code is allowed to use this. static means main can start without building an object first. void means main does not hand a value back. Treat these three words as part of the frame until the methods lesson.
      5. 
        
    5. // starts a comment. Java skips the rest of that line. Comments are notes for people.
      6. 
        
    6. System.out.println("Hello"); prints Hello and ends with a semicolon.
      7. 
      
    
      
    Tip. Java cares about capital letters. System and system are different. Text uses double quotes. A comment uses // and is not printed.
    
      
    Before and after
    
      
    
        
    
          
    Before
    

    System.out.println("Hello")

    After
    

    System.out.println("Hello");
    
          
    The semicolon ends the statement. This line can compile.

    Key takeaway. Statements end with semicolons, groups use braces, text uses double quotes, and the public class name matches the file name.

    Variables and types
    
      
    A variable is a labeled box that holds one value. The type says what kind of value the box may hold.
    
      
    You create a box with a declaration: the type, then the name, then =, then the value. The word assign means "put this value into the box." A later assignment replaces what was inside. It does not create a second box.
    
      
    Analogy. A closet has labeled boxes. The label is the variable name. The kind of box is the type: a tray for whole numbers, a jar for decimals, a switch for yes or no, a folder for text. Java refuses to put text into a whole-number tray.

    Operators
    
      
    An operator is a symbol that does a job on values, such as adding them or asking whether they are equal.
    
      
    = is not a question. It stores the value on the right into the box on the left. == is the question "are these equal?" Mixing them up is one of the most common early bugs.
    
      
    Analogy. Arithmetic operators are calculator buttons. Comparison operators are yes-or-no questions. The remainder operator % is what is left after you share cookies evenly: 10 cookies and 3 friends means each friend gets 3, and 1 cookie remains.
    
      
    Sharing 10 cookies
    
      
    Java, inside main:
    

    int cookies = 10;
int friends = 3;
int each = cookies / friends;
int leftover = cookies % friends;
System.out.println(each);
System.out.println(leftover);

    3
1

      2.

      3. 
        
    3. cookies % friends is the remainder, 1. % is pronounced "mod."
      4. 
        
    4. The prints show 3, then 1. Nothing in the program rounds 3.333 up to 4.

    Input and output
    
      
    Output is what the program prints. Input is what a person types while the program is running.
    
      
    System.out.println prints and then moves to the next line. System.out.print prints and stays on the same line. To listen to the keyboard, Java uses a Scanner. You create one, then ask it for a line of text or a whole number.
    
      
    Analogy. println is speaking a sentence and taking a breath. print is speaking and staying on the same line so the person can answer beside the question. A Scanner is the program's ears.
    
      
    Ask for a name
    
      
    Java:
    

    import java.util.Scanner;

public class AskName {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        System.out.print("Your name: ");
        String name = input.nextLine();
        System.out.println("Hello, " + name);
        input.close();
    }
}
    
      
    If the person types Maya, the output is:
    
      
    Your name: Maya
Hello, Maya
    
      
    Line by line
    
      
      
        
    1. import java.util.Scanner; tells Java where the Scanner type lives. Import lines go above the class.
      2. 
        
    2. Scanner input = new Scanner(System.in); builds a listener named input. System.in means the keyboard. new builds it.
      3. 
        
    3. print, not println, shows the question and leaves the cursor on that line.
      4. 
        
    4. nextLine() waits until Enter, then returns the whole line, spaces included. The parentheses mean "do this action now."
      5. 
        
    5. "Hello, " + name joins text. The + operator adds numbers, and it also joins text when either side is text.
      6. 
        
    6. input.close(); says you are done listening. In a one-read practice program, this is the usual last step.
      7. 
      
    
      
    
        
    
          
    print
    

    System.out.print("Hi");
System.out.print("Maya");
    
          
    Output: HiMaya on one line.
    
        
    
        
    
          
    println
    

    System.out.println("Hi");
System.out.println("Maya");
    
          
    Output: Hi, then Maya on the next line.

    Decisions
    
      
    if runs a group of lines only when a yes-or-no test is true. else runs when that test is false.
    
      
    The test goes in parentheses and must be a boolean: true or false. Comparison operators such as >= produce that boolean. You can chain more tests with else if. Java checks them from top to bottom and runs only the first match.
    
      
    Analogy. A decision is a fork in a path. The sign says "score at least 60." If the sign is true, you take the Pass path. If it is false, you take the other path. You do not walk both paths.
    
      
    Pass or try again
    
      
    Java, inside main:
    

    int score = 72;
if (score >= 60) {
    System.out.println("Pass");
} else {
    System.out.println("Try again");
}
    
      
    Output:
    
      
    Pass
    
      
    Line by line
    
      
      
        
    1. int score = 72; stores the input.
      2. 
        
    2. if (score >= 60) asks the question. 72 >= 60 is true. There is no semicolon here. The brace group is the body.
      3. 
        
    3. Because the test is true, Java prints Pass and skips else.
      4. 
        
    4. If the score were 59, the test would be false and Java would print Try again instead.
      5. 
      
    
      
    A letter-grade chain
    
      
    Java, inside main, for the same score 72:
    

    if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B");
} else if (score >= 70) {
    System.out.println("C");
} else if (score >= 60) {
    System.out.println("D");
} else {
    System.out.println("F");
}
    
      
    Output:
    
      
    C
    
      
    72 fails the A test and the B test. It passes the C test, so Java prints C and does not look at D or F.
    
      
    
        
    
          
    Before
    

    if (score >= 60); {
    System.out.println("Pass");
}
    
          
    The semicolon ends the if immediately. The print is no longer inside the decision, so it runs even when the score fails.
    
        
    
        
    
          
    After
    

    if (score >= 60) {
    System.out.println("Pass");
}
    
          
    The brace group belongs to the if. Pass prints only when the test is true.

    Loops
    
      
    A loop repeats a group of lines while a test stays true.
    
      
    Use a for loop when you can count the repeats. Use a while loop when you should keep going until a situation changes. Both need a test that can eventually become false. Otherwise the program repeats forever.
    
      
    Analogy. "Run 3 laps" is a for loop: you know the count before you start. "Stir until the sauce thickens" is a while loop: you check the sauce, stir, and check again. If you never look at the sauce, you would stir forever.
    
      
    Three laps
    
      
    Java, inside main:
    

    for (int i = 1; i <= 3; i++) {
    System.out.println("Lap " + i);
}
    
      
    Output:
    
      
    Lap 1
Lap 2
Lap 3
    
      
    Line by line
    
      
      
        
    1. int i = 1 runs once, before the first lap. i is the counter.
      2. 
        
    2. i <= 3 is checked before every lap. When it is false, the loop stops.
      3. 
        
    3. The body prints Lap joined to the current number.
      4. 
        
    4. i++ means i = i + 1. It runs after the body, then Java checks the test again.
      5. 
        
    5. So i becomes 1, 2, and 3. When i becomes 4, 4 <= 3 is false and nothing more prints.
      6. 
      
    
      
    
        
    
          
    for, when you can count
    

    for (int i = 1; i <= 3; i++) {
    System.out.println("Lap " + i);
}
    
        
    
        
    
          
    while, same three laps

    Methods
    
      
    A method is a named action you can run again by calling its name.
    
      
    You have already called methods. println and nextLine are methods other people wrote. A call is the moment you use the name, usually with parentheses. Now you will write your own.
    
      
    A parameter is a box in the method's definition, waiting for a value. An argument is the value you hand in at the call. return sends a value back to the caller and leaves the method. void means "this method does not send a value back."
    
      
    Analogy. A coffee-machine button is a method. "Beans" and "water" printed on the machine are parameters. The beans you insert are arguments. The cup that comes out is the return value. Printing a message is like the machine beeping. The beep is not the cup. If you needed the cup, a beep is not enough.
    
      
    Add two scores
    
      
    Java:
    

    public class Adder {
    public static int add(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        int total = add(80, 55);
        System.out.println(total);
    }
}

      2. 
        
    2. return a + b; adds the two numbers and hands the sum back.
      3. 
        
    3. main still starts the program. Defining add does not run it.
      4. 
        
    4. add(80, 55) calls the method. 80 and 55 are the arguments. They are copied into a and b.
      5. 
        
    5. int total = ... stores the returned 135. Then println prints that stored value.
      6. 
      
    
      
    
        
    
          
    Before
    

    public static int add(int a, int b) {
    System.out.println(a + b);

    The method promised an int and did not return one. Printing is not returning. This file does not compile.

    Arrays
    
      
    An array is a numbered row of boxes that share one name. The position number is the index, and the first index is 0.
    
      
    One int holds one score. An int[] holds a row of scores. You read a box with scores[0], scores[1], and so on. scores.length is how many boxes exist. It has no parentheses. The last valid index is length - 1, not length.
    
      
    Analogy. A row of mailboxes is numbered starting at 0, not 1. If four mailboxes exist, they are 0, 1, 2, and 3. Asking for mailbox 4 does not wrap around. There is no mailbox 4.
    
      
    Four quiz scores
    
      
    Java, inside main:
    

    int[] scores = {80, 55, 90, 70};
System.out.println(scores[0]);
System.out.println(scores.length);

    Write the goal in plain words before you write Java. Code is the last step, not the first.

    Project: score report
    
      
    Build one program that stores four scores, labels each as Pass or Fail, and prints the average.
    
      
    This uses the whole toolbox. Variables hold the pass mark and the average. An array holds the scores. A loop visits each score. An if chooses Pass or Fail. A method named average returns the decimal average. Scanner reads the four numbers from the keyboard. On this page, the number boxes stand in for that typing.
    
      
    Analogy. A teacher walks a row of mailboxes. At each box she says the score and whether it passed. After the row, she announces the class average. The loop is the walk. The method is the average calculation she can reuse.
    
      
    The Java program
    
      
    Java:
    

    import java.util.Scanner;

public class ScoreReport {
    public static double average(int[] scores) {
        int sum = 0;
        for (int i = 0; i < scores.length; i++) {
            sum = sum + scores[i];
        }
        return sum / (double) scores.length;
    }

    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        int[] scores = new int[4];

        for (int i = 0; i < scores.length; i++) {
            System.out.print("Score " + (i + 1) + ": ");
            scores[i] = input.nextInt();
        }

        int passMark = 60;

        for (int i = 0; i < scores.length; i++) {
            if (scores[i] >= passMark) {
                System.out.println("Score " + (i + 1) + ": " + scores[i] + " Pass");
            } else {
                System.out.println("Score " + (i + 1) + ": " + scores[i] + " Fail");
            }
        }

        double avg = average(scores);
        System.out.println("Average: " + avg);

        if (avg >= passMark) {
            System.out.println("Class result: Pass");
        } else {
            System.out.println("Class result: Fail");
        }

        input.close();
    }
}
    
      
    Sample output for 80, 55, 90, and 70, with pass mark 60:
    
      
    Score 1: 80 Pass
Score 2: 55 Fail
Score 3: 90 Pass
Score 4: 70 Pass
Average: 73.75
Class result: Pass
    
      
    Line by line
    
      
      
        
    1. average starts a sum at 0, adds scores[i] for each index, and returns one double.
      2. 
        
    2. (double) converts the count before the division. Without it, 295 / 4 would be the int 73. With it, the result is 73.75.
      3. 
        
    3. new int[4] builds four boxes, indexes 0 through 3, before any scores are typed.
      4. 
        
    4. The first loop prints Score 1 through Score 4. It adds 1 to the index so a person does not have to read a report numbered from 0.
      5. 
        
    5. nextInt stores each typed whole number into the current box.
      6. 
        
    6. The second loop tests scores[i] >= passMark and prints Pass or Fail. One failing score does not stop the loop.
      7. 
        
    7. average(scores) calls the method. The array is the argument. avg stores the return value.
      8. 
        
    8. The last if compares that average with the same pass mark.
      9. 
      
    
      
    
        
    
          
    Before
    

    return sum / scores.length;
    
          
    With the sample, sum is 295 and length is 4. Both are ints, so the returned value is 73. The fraction is gone.
    
        
    
        
    
          
    After
    

    return sum / (double) scores.length;
    
          
    295 / 4.0 is 73.75. The report keeps the fraction.

    Key takeaway. The report is a loop around a decision, plus a method that returns the average. Each tool does one job you already practiced.
